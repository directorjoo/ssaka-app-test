## 알아둘 점

- 서버가 없어서 비용 0원. 카드 내용은 링크 안에 들어 있고, 기록은 각자 휴대폰에만 저장됩니다.
- 카카오디벨로퍼스 앱 이름을 "싸카"로 바꾸면 카톡 카드 아래 출처가 싸카로 나옵니다.
- 카톡 미리보기가 안 바뀌면: 카카오디벨로퍼스 → 도구 → 카카오톡 URL 메타정보 관리 → 캐시 초기화

진행 상황은 [docs/ROADMAP.md](docs/ROADMAP.md), 사업계획은 [docs/BUSINESS_PLAN.md](docs/BUSINESS_PLAN.md).


## 식당 예약 서버 연결 (v4)

식당 카드의 `reserve` 설정에 고유한 `shop_key`를 지정하면 예약 폼이 `POST /api/reservations`로 예약 요청을 직접 접수합니다. `shop_key`가 없는 기존 카드는 문자 발송 방식으로 계속 동작합니다.

예시:
```js
reserve: {
  label: '예약하기',
  shop_key: 'restaurant-unique-key',
  menu: [{ n: '대표 메뉴', p: 18000 }]
}
```

Cloudflare Pages 배포 시 `functions/api/reservations/[[id]].js`와 D1 바인딩 `DB`, Secret `SSAKA_ADMIN_KEY`가 필요합니다. 관리자 화면은 `/admin/`입니다. 예약 생성 API 연결은 완료됐지만, 고객에게 자동 문자/알림톡을 보내는 기능은 별도 발송사 연동이 필요합니다.

## 매장별 입점·관리자 인증 (v5)

- `/admin/`에서 매장명과 전화번호로 신규 매장을 등록할 수 있습니다.
- 등록 시 매장별 `shop_key`와 관리자 전용 `admin_key`를 발급합니다.
- 관리자 인증 키는 SHA-256 해시로 D1에 저장하며, 원문 키는 등록 직후 한 번만 반환합니다.
- 신규 매장은 자신의 관리자 키로만 해당 매장의 예약 목록 조회 및 상태 변경이 가능합니다.
- 기존 전역 `SSAKA_ADMIN_KEY`로 운영하던 매장은 하위 호환을 위해 유지됩니다. 신규 매장에는 매장별 키 사용을 권장합니다.

Cloudflare Pages에서 `DB` D1 바인딩이 필요합니다. `functions/api/shops.js`가 신규 입점 API이며 `POST /api/shops`로 매장 등록을 처리합니다. 실제 운영 전에는 CAPTCHA/요청 제한, 사업자 확인, 관리자 키 재발급·분실 절차, 개인정보 처리방침과 보관기간 정책을 추가해야 합니다.

### v6 매장 운영 기능
- `/admin/`에서 매장별 관리자 키로 인증한 뒤 예약을 확인하고 매장명·전화번호를 수정할 수 있습니다.
- `GET /api/shops/:shop_key`: 인증된 매장의 프로필 조회
- `PATCH /api/shops/:shop_key`: 인증된 매장의 매장명·전화번호 수정
- Cloudflare Pages Functions 환경에 D1 바인딩 이름 `DB`가 필요합니다.
- 이 ZIP은 소스코드이며 실제 Cloudflare 배포·도메인 연결·실예약 테스트는 포함하지 않습니다.

## v15 서버 권한 및 요금제 제한
- `GET /api/entitlements?shop_key=...`: 매장 관리자 인증 후 현재 유효한 플랜과 서버 기준 권한/한도를 반환합니다.
- 만료되었거나 유효하지 않은 구독은 서버에서 스타터(무료) 권한으로 자동 강등 처리합니다.
- 무료 플랜은 매월 예약 요청 30건으로 제한하며 초과 시 `429 RESERVATION_MONTHLY_LIMIT`를 반환합니다.
- 매장 통계 조회는 플러스/프로 권한이 필요하며 무료 플랜은 `403 ANALYTICS_REQUIRES_PLUS`를 반환합니다. 이벤트 수집은 유지하므로 유료 전환 시 통계 활용이 가능합니다.
- `/api/billing/subscription` 응답에 서버 계산 권한 정보가 포함됩니다.
- 권한 판정은 클라이언트 표시값이 아니라 D1의 `shop_subscriptions` 상태와 만료 시각을 기준으로 합니다.
- 디자인 템플릿 수와 직원 계정 수는 권한 API에 한도를 제공하는 단계입니다. 실제 템플릿 저장/직원 계정 생성 API가 별도로 연결되기 전까지 해당 한도가 모든 화면/API에 강제되는 것은 아닙니다.
- Toss 결제는 기존과 동일하게 30일 단건 결제이며 자동 정기결제는 지원하지 않습니다. 실제 결제·운영 배포 검증은 별도 필요합니다.

## v17 — 고객용 매장 페이지 자동 연결

- 공개 조회 전용 `GET /api/public/shops/:shop_key`를 추가했습니다. 매장명·전화번호·주소·소개·대표 이미지와 공개 메뉴 항목만 반환하며 관리자 인증 해시 등 비공개 정보는 반환하지 않습니다.
- 고객용 카드 뷰어에서 `?shop=<shop_key>`를 읽어 공개 매장 정보를 기존 카드 데이터에 반영합니다.
- 관리자 화면의 매장 정보 영역에 고객용 페이지 링크와 링크 복사 기능을 추가했습니다. URL 형식은 `/demo/?card=shop&shop=<shop_key>`입니다.
- 고객 페이지는 기존 싸카 렌더러를 사용하므로 메뉴 사진·설명·가격·품절·대표 메뉴 스타일과 전화·길찾기 동작이 이어집니다.
- 공개 메뉴 API는 60초 캐시를 사용합니다. 변경사항이 즉시 반영되어야 할 운영에서는 캐시 정책 조정이 필요합니다.
- 검증 범위: JavaScript 문법 및 ZIP 무결성. D1 실제 마이그레이션, Cloudflare Pages 배포, 모바일 브라우저 실동작은 운영환경에서 검증해야 합니다.

### 공개 페이지 연결 방법
1. `/admin/`에서 매장 식별 키와 관리자 키로 로그인합니다.
2. 매장 정보와 메뉴를 저장합니다.
3. `고객용 매장 페이지` 링크를 복사해 카카오톡 등에 공유합니다.
4. 링크 예: `https://서비스도메인/demo/?card=shop&shop=발급된매장키`

## v27 고객 관리(CRM)
- 매장 관리자 전용 고객 등록·검색·삭제 및 방문 횟수 기록 API를 추가했습니다.
- 고객명·연락처 저장은 관리자 화면에서 고객 동의 체크가 있어야 가능합니다.
- 고객 정보는 매장별로 분리되며 관리자 인증 헤더를 확인합니다.
- 고객의 연락처는 개인정보이므로 접근 통제, 보유기간, 파기 절차와 개인정보 처리방침을 실제 서비스 출시 전에 마련해야 합니다. 동의 체크는 운영자가 확인하는 절차이며 법률상 적법한 동의 절차를 자동으로 보장하지 않습니다.


## v28 단골 고객 분류 및 재방문 분석
- 고객관리 화면에 신규(방문 0~1회), 관심(2~3회), 단골(4회 이상), 휴면 후보(마지막 방문 30일 이상) 그룹 필터를 추가했습니다.
- 방문 +1 처리 시 `shop_customer_visits`에 방문 시각을 별도 기록해 이후 방문 간격을 계산합니다.
- 고객관리 API는 최근 30일 방문 로그 수를 요약에 포함합니다.
- 평균 방문 간격은 v28 도입 이후 새로 기록된 방문 로그만을 기준으로 계산하며, 과거 방문 횟수만 있는 고객의 이전 방문 날짜는 복원하지 않습니다.
- 자동 마케팅 메시지 발송은 포함하지 않습니다. 고객 동의 및 관련 법령을 확인한 뒤 매장 관리자가 직접 쿠폰을 공유해야 합니다.


## v29 고객별 맞춤 쿠폰 추천
- 고객 그룹과 방문 이력에 따라 신규·재방문·단골 고객용 쿠폰 초안을 추천합니다.
- 고객 목록의 `맞춤 쿠폰 추천`을 누르면 기존 쿠폰 발행 폼에 제목, 안내 문구, 할인율, 유효기간, 1회 발급 수량을 채웁니다.
- 쿠폰 발행은 관리자가 기존 쿠폰 API와 요금제 권한을 통해 직접 확정합니다. 추천 버튼만으로 쿠폰이 발행되거나 고객에게 메시지가 발송되지 않습니다.
- 고객별 고유 쿠폰 소유권·개별 사용 제한을 보장하는 기능은 아닙니다. 쿠폰은 매장 공개 쿠폰으로 발행되며 1회 수량 제한은 쿠폰 전체 사용 수량 기준입니다.
- 고객 연락처를 이용한 자동 메시지 발송은 포함하지 않습니다. 고객의 구체적 동의와 관련 법령을 확인한 뒤 직접 전달해야 합니다.


## v30 쿠폰 사용 이력 및 재방문 전환 분석
- 쿠폰 사용 처리 시 매장별 사용 원장(shop_coupon_redemptions)에 사용 시각과 선택적 CRM 고객 ID를 기록합니다.
- CRM 고객 ID 연결은 해당 매장에 등록되고 동의(consent=1)된 고객만 허용합니다. 고객 연결은 관리자 사용 처리 화면에서 선택적으로 입력하며, 입력하지 않아도 쿠폰 사용 기록은 남습니다.
- 쿠폰 관리 화면에 최근 30일 사용 건수, 고객 연결 사용 건수, 고객 연결률, 2회 이상 쿠폰 사용 고객 수를 표시합니다.
- 고객 ID를 모르면 미연결로 처리됩니다. 기존 과거 쿠폰 사용 건은 원장에 소급 생성되지 않습니다.
- 이 기능은 쿠폰 사용 기록 기반이며 실제 매출/순이익/방문 인과관계를 증명하지 않습니다. 운영 적용 전 D1 백업, 개인정보 고지 및 보유기간 검토가 필요합니다.
