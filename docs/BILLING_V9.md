# 싸카 v9 결제 연동 기반

## 구현 범위
- `GET /api/plans`: 요금제 카탈로그
- `POST /api/billing/order`: 매장 관리자 인증 후 서버 가격표로 주문 생성
- `POST /api/billing/confirm`: Toss Payments 승인 API에 서버가 직접 요청하고 결제 상태·금액을 검증한 뒤 30일 이용권 활성화
- `POST /api/billing/subscription`: 매장 구독 상태 조회
- `/billing/`: 매장 키·관리자 키 입력, 플러스/프로 선택, 결제창 진입
- `/billing/success.html`: 결제 리다이렉트 결과를 서버에 보내 최종 승인 검증
- `/billing/fail.html`: 결제 실패 안내

## Cloudflare 설정
1. Pages 프로젝트에 D1 바인딩 `DB`가 연결되어 있어야 합니다. 기존 예약 기능이 사용하는 DB와 같은 바인딩 이름을 사용합니다.
2. 환경변수(Secrets)에 `TOSS_CLIENT_KEY`, `TOSS_SECRET_KEY`를 등록합니다.
3. Toss Payments 상점 계약 및 결제수단 심사를 완료하고, 운영 도메인을 결제 리다이렉트 허용 도메인으로 설정합니다.
4. `/billing/`에서 실제 카드 결제와 취소/실패/중복 승인 시나리오를 테스트합니다.

## 중요 제한
- 이 버전은 **30일 단위의 단건 결제**입니다. 카드 자동 정기결제/빌링키 저장/자동 갱신은 구현하지 않았습니다.
- 실제 결제는 Toss 상점 계약, 키 발급, 도메인 등록 및 배포 후에만 가능합니다. 키가 없으면 주문 생성 응답은 결제 설정 안내를 반환합니다.
- 결제 승인 성공 후 D1 구독 상태가 활성화됩니다. 그러나 예약 API 등 모든 유료 기능의 서버측 권한 차단은 아직 전 구간에 적용되지 않았습니다. 상용 유료 출시 전에 반드시 공통 권한 미들웨어를 모든 유료 기능 API에 적용해야 합니다.
- 환불/부분취소/세금계산서/현금영수증/정기결제/결제 웹훅 및 정산 자동화는 후속 작업입니다.
- `sessionStorage`에 결제 흐름 동안 매장 관리자 키를 보관합니다. 운영 전에는 매장별 세션 토큰으로 교체하고 관리자 키 재발급·회수 및 CSRF/요청 제한 정책을 강화하는 것이 권장됩니다.

## 서버 검증 원칙
- 결제 금액은 브라우저 값이 아니라 서버의 고정 요금표에서 주문 생성 시 결정합니다.
- 결제 승인 시 주문 ID, 매장 소유권, 금액, 주문 만료 여부를 확인합니다.
- 최종 승인 여부는 Toss Payments 승인 API 응답으로 검증합니다. 브라우저 리다이렉트만으로 구독을 활성화하지 않습니다.

## v15 권한 적용 추가
서버 권한 조회는 `/api/entitlements`를 사용합니다. 무료 플랜 예약 30건/월 제한과 통계 조회 플러스 이상 제한이 API에서 적용됩니다. 디자인 템플릿·직원 계정 한도는 entitlement 응답에 포함되며 관련 CRUD API 연결 전까지 완전 강제되지 않습니다.
